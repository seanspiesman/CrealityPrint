# Evidence for reliable model acquisition and print preparation

**Question:** What can be checked automatically when an agent acquires a free public model or opens an existing file, and what decision inputs are needed before a reliable FDM print can be prepared?

## Finding

**Recommendation inferred from the sources below:** preparation should be a reviewable pipeline: acquire and record the source; parse the model as untrusted input; resolve units and intended scale; inspect geometry; select a compatible local printer/process/material profile; evaluate orientation, support, fit and estimated resource use; slice with the selected profiles; then show a preview and provenance before queueing. The slicer can answer geometric and process questions. It cannot infer every model’s purpose, required load, mating tolerance, exposure conditions, or acceptable failure consequence. If those facts affect material, orientation, wall design, or dimensions, ask rather than inventing them.

The owner’s stated policy is: broad FDM objects; public free downloads and owned files; show candidate designs for agent-led searching; reliability is the default priority; explicit user settings prevail; stop and ask on preparation uncertainty. The owner grants broad model-preparation/modification/generation authority, so routine authorized operations do not require fresh approval. Ask when dimensions, fit, intended use or a proposed change remain uncertain, rather than treating every substantial edit as an approval gate. No exact owner-supplied dimensions or intended load have been provided. The named printer fleet is one K1 Max, three K1 SE, and two Creality Hi; hardware attachments and printer-side profiles remain unverified by this research.

## Acquisition and provenance

For an agent-selected design, present candidate source, preview, creator, license/attribution as published, file formats, model version, and any required assembly or material notes before committing to a file. Keep the original download unchanged and record canonical source URL, retrieval time, file name, cryptographic hash, listed license, and chosen variant. For user-supplied files, retain the local path and hash. This allows later jobs to name exactly which geometry was prepared and helps distinguish original from repaired/rescaled variants.

Treat arbitrary user-provided URLs as a network boundary: accept only intended schemes, validate the final destination after redirects (or disable redirects), reject localhost/private/link-local targets, bound response size/time, and restrict archive extraction paths and expanded size. OWASP specifically recommends application and network defenses for SSRF, allowlisting where destinations are known, and disabling redirects that can bypass validation. [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

Do not trust embedded G-code or project settings just because a file is a 3MF. The 3MF Core standard defines a ZIP/XML model container, units, meshes, build items, metadata and extensions; slicers may add application-specific data. This Creality Print checkout’s 3MF importer recognizes embedded machine, process and filament preset entries, while its exporter can include `Metadata/plate_N.gcode`; the public command-line workflow also allows explicit printer/process and filament JSON presets for STL/OBJ. Therefore the preparation service should inspect imported settings, report changes, and re-slice against the chosen local printer and material profiles before dispatch. [3MF Core Specification source](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md), [Creality Print 3MF importer/exporter at inspected revision](https://github.com/CrealityOfficial/CrealityPrint/blob/59ae8cbb0437dcc7236e27433ecd4aeb52be0244/src/libslic3r/Format/bbs_3mf.cpp), [Creality Print CLI documentation at inspected revision](https://github.com/CrealityOfficial/CrealityPrint/blob/59ae8cbb0437dcc7236e27433ecd4aeb52be0244/README.md#command-line-slicing)

## Units, geometry and transformation policy

STL stores coordinates without a standardized physical unit, so a slicer’s millimeter interpretation can turn an intended inch-sized model into a 25.4-times scale error. 3MF Core has an explicit unit attribute whose default is millimeter and supports micron, millimeter, centimeter, inch, foot, and meter. The Creality Print reader in this checkout maps those unit values into millimeter scale factors. For STL, preserve raw coordinate bounds and apply the common mm interpretation only as an explicit assumption; if the size is implausible or conflicts with the request, show the dimensions and ask. Never infer owner dimensions from the printable volume or from a guessed use. [3MF Core units and default](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md), [3D Slicer STL coordinate/unit limitation](https://slicer.readthedocs.io/en/latest/user_guide/data_loading_and_saving.html), [Creality Print unit conversion at inspected revision](https://github.com/CrealityOfficial/CrealityPrint/blob/59ae8cbb0437dcc7236e27433ecd4aeb52be0244/src/libslic3r/Format/bbs_3mf.cpp)

Preflight can compute bounding dimensions, connected components, open/nonmanifold edges, degenerate facets, inverted normals, self-intersections, minimum feature thickness, and whether a candidate orientation fits the currently selected profile’s build envelope. 3MF Core requires manifold edges, consistent triangle orientation, and outward normals for solid model meshes. A slicer may still import and attempt to repair malformed STL; in this checkout, STL import repair checks exact and nearby faces and removes unconnected facets, while the source comments that hole filling is disabled because it can harm complex holes. The code tracks repair counters such as edges fixed, facets removed/reversed, and degenerate facets. A successful slice is not proof that a repair preserved design intent. Keep the source mesh and record before/after repair statistics. Raise unresolved design or dimensional uncertainty about a repair, split, scale or Boolean operation; do not add a blanket approval gate for operations the owner already authorized. [3MF Core mesh requirements](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md), [Creality Print STL repair code at inspected revision](https://github.com/CrealityOfficial/CrealityPrint/blob/59ae8cbb0437dcc7236e27433ecd4aeb52be0244/src/libslic3r/TriangleMesh.cpp)

The source project format itself may contain multiple plates, transformed instances, painted/color assignments, and per-object settings. The implementation should present the object count, parts/assemblies, selected plate, dimensions after transforms, material/color mapping, and any embedded profile mismatch. A “model is valid” state should therefore be distinct from “this exact prepared plate was sliced and previewed.”

## What can be selected by rules, and what needs user intent

**Usually rule-checkable from file and verified printer/profile data:** unit declaration or unit ambiguity; bounding box and fit; whether the mesh passes stated validity checks; number of objects/plates; nozzle diameter and process profile match; required material profile availability; basic overhang/support regions; orientation candidates; support volume and contact area; and a slicer estimate for time and filament. Select only among profiles verified for that printer’s current hardware and the actual loaded spool/CFS mapping. If a needed profile/hardware fact is unknown, hold and ask.

**Needs user intent or calibrated evidence:** exact size for an object without trustworthy units; mating fit/tolerance; whether a part is decorative, flexible, load-bearing, hot, UV/weather exposed, or safety-critical; which direction bears load; acceptable surface marks from supports; whether seams, weak points, or visible surfaces are acceptable; and material substitution. User-requested setting values override automatic defaults where compatible. If an explicit setting conflicts with hardware/material constraints or the model cannot fit, explain the conflict and ask.

Orientation is multi-objective. A face-down orientation may reduce support and improve appearance, while another orientation may shorten print time, improve bed contact, or put layer interfaces in a different direction relative to load. Prusa’s documentation gives 45–60° as a general overhang range dependent on nozzle and settings and notes that support-facing surfaces have different finish; its models with specialized cooling can exceed that range, illustrating why generic thresholds cannot be applied uniformly. [Prusa orientation and support guidance](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135)

“Strong” is not a value that can be inferred from mesh appearance. FFF/FDM printed mechanical behavior varies with build orientation and raster angle; published tensile testing across different materials shows anisotropy and different outcomes by layup. Perimeters and infill affect structure, but a higher infill percentage alone does not establish suitability for a load. If an intended use depends on load, fatigue, impact, elevated temperature, or failure consequences, ask for requirements and treat any strength estimate as unverified until supported by material/process-specific tests or engineering analysis. [Experimental study of orientation and raster effects across FFF materials](https://pmc.ncbi.nlm.nih.gov/articles/PMC11728033/), [Prusa overview of perimeters and infill](https://help.prusa3d.com/article/first-print-with-prusaslicer-3-0-0_1079761)

Material compatibility must bind to a printer/nozzle/hotend profile and a verified actual filament, not just a color label embedded in a project. Manufacturer guidance for even one material can include nozzle, bed, sheet, enclosure, drying, and special profile requirements; abrasive-filled filament may require a hardened nozzle. Therefore model colors should map to stocked spool records with material family and exact color; missing/ambiguous records or unavailable exact color trigger the owner’s stated “offer alternatives and ask” behavior. [Prusa material and hardware matching example](https://help.prusa3d.com/article/using-the-ht-hotend_1225792?product=accessories-add-ons), [Prusa abrasive composite notes](https://help.prusa3d.com/article/composite-materials-with-metal-or-wood-particles_166863)

## Slicing, estimates and review evidence

The selected printer/process/material profile plus geometry produce the toolpath. Creality Print documents CLI slicing with explicit preset JSON files and command outputs; this can support background preparation and repeatability. A saved 3MF is useful as an inspectable project, but the review should state which settings came from the source project, which came from verified local presets, and which the agent selected. Show any transform/repair, dimensions, fit margin, orientation rationale, supports, layer/perimeter/infill choices, color/material assignments, sliced preview, time and filament estimates, and warnings. Prusa’s documented preview is where the generated instructions are checked; its overview also notes perimeters/infill affect strength, time, and consumption. [Creality Print CLI slicing at inspected revision](https://github.com/CrealityOfficial/CrealityPrint/blob/59ae8cbb0437dcc7236e27433ecd4aeb52be0244/README.md#command-line-slicing), [Prusa slicing and preview workflow](https://help.prusa3d.com/article/first-print-with-prusaslicer-3-0-0_1079761)

Treat time and filament quantities as slicer estimates. The estimate depends on the exact toolpath, purge/color-change behavior, printer profile and its speed/flow limits; it does not prove actual runtime, remaining spool, or successful completion. Record slicer version, profile identifiers/versions, resulting G-code/project hash, estimated time and filament, and actual outcome separately when known. For broad “anything I want to print” use, reliability ranking should prioritize a verified compatible preset, a well-supported orientation, low repair ambiguity, and known material availability; it should ask before changing explicit user settings or choosing unsupported assumptions.

The review evidence should remain available in the project/job record; it is not a new mandatory per-print approval gate. The owner's explicit gates are candidate selection after agent-led search, preparation uncertainty, proposed material/color substitutions, and exceeding configured resource limits. Routine authorized preparation may continue automatically when those conditions are satisfied.

## Recommended preparation acceptance

Before a prepared job is eligible for automatic queue/start, require:

1. Source provenance and a stable hash are recorded; unsupported URL types or unsafe archive behavior are rejected.
2. Units and final dimensions are known or explicitly accepted; ambiguous STL scale is displayed and resolved.
3. Mesh checks and any repair or authorized modification are summarized; unresolved geometry, dimensional or intended-use uncertainty holds the job and is raised with the owner. Broadly authorized operations may proceed without another approval when the required inputs are established.
4. Exact printer profile, nozzle/hardware, material and color are matched to current verified records; unavailable or unknown facts hold the job.
5. The sliced plate fits that printer’s configured printable envelope and has no unresolved warnings; support and orientation choices are visible.
6. Source-embedded G-code/settings are not silently trusted; the job is re-sliced with approved local profiles and a resulting project/G-code hash is recorded.
7. The review records assumptions, estimates and unresolved limitations. For load-bearing or safety-relevant claims, preparation does not claim strength or fit without user requirements and relevant validation.
