# Model authoring options for the local agent workflow

## Finding

Creality Print already covers useful **print-preparation edits** on imported models, but it is not a general-purpose design system. Use its GUI action surface for plate-level scaling, rotation/movement, splitting, repair/simplification, auto-orientation and arrangement. For newly generated or dimension-driven parts, call a dedicated CAD/mesh program through the local service and keep its editable source next to the exported STL/3MF and Creality project. A practical first tool set is FreeCAD for fit-critical parametric parts, OpenSCAD for simple repeatable CSG parts, and Blender only when organic/artistic mesh work is requested. The recommendation is an inference from their documented interfaces; none was installed, called, or quality-tested here.

“Everything” authoring authority allows the agent to perform requested operations. It does not supply missing design intent, dimensions, tolerance, material/loads, or fit references. When those determine whether an object works, the agent should hold for answers.

## What Creality Print already provides

- `scale_object` takes per-axis scale factors and object/plate/all scope. [`SlicerBridgeActionRegistry.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionRegistry.cpp#L404). Implementation requires positive factors and changes geometry/instances via the GUI plater ([`SlicerBridgeActionsObject.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionsObject.cpp#L1824)). For a fit-critical part, the service should request a target dimension/axis and expected units; it should not invent isotropic scaling as a design fix.
- `move_object` supports object offsets and optional bed-boundary/clearance correction, with defaults for margin and clearance in mm. [`SlicerBridgeActionRegistry.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionRegistry.cpp#L367). These are slicer placement checks, not mechanical assembly fit.
- `rotate_object`, `auto_orient`, and `auto_arrange` can change orientation/placement. Auto-orient optimizes support area, support volume or time and may be asynchronous on CPU fallback ([`SlicerBridgeActionsProcess.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionsProcess.cpp#L130)). It does not optimize strength direction, appearance, dimensional accuracy, or heat/load performance unless another explicit objective is supplied.
- `split_model` currently chooses a Z cut height, defaults to the vertical midpoint, clamps it to leave at least 0.1 mm from bounds, cuts one target instance, then adds resulting objects to the GUI model with undo support ([implementation](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionsObject.cpp#L3375)). No arbitrary plane, keyed joint, fastener geometry or print-in-place connector is represented in this tool schema. Those require CAD or more detailed inputs.
- `repair_mesh` repairs selected meshes with geometry errors; `simplify_model` uses quadric edge collapse. [`SlicerBridgeActionRegistry.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionRegistry.cpp#L273) [`SlicerBridgeActionRegistry.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionRegistry.cpp#L285). Repair is a mesh-integrity operation, not a semantic repair of missing geometry or an assurance of watertightness/print strength. Simplification trades surface detail for triangle count; target ratio alone does not express which details must be preserved.
- Existing procedural shapes exposed as `add_test_model` include primitives and calibration/demo models, not an extensible shape grammar. [`SlicerBridgeActionRegistry.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionRegistry.cpp#L547). Treat those as test geometry, not a replacement for authoring tools.

## Suggested local MCP/API boundary

Expose a narrow, model-agnostic tool contract that dispatches to separate authoring adapters rather than asking the agent to express every action as ad hoc GUI mutations:

1. `analyze_model` returns file type, units/extent, object and shell counts, mesh validity indicators, slicer warnings, and whether the source is parametric or triangle-only.
2. `author_parametric_part` takes an explicit requirement/parameter object and a chosen FreeCAD/OpenSCAD backend; returns editable source/document, source hash, parameter manifest and exported mesh.
3. `modify_mesh` routes artistic/sculpt/remesh work to Blender; asks for mesh-only requirements, preserves the original, and emits an editable scene plus exported mesh.
4. `prepare_in_creality` imports the accepted mesh into a project, performs only specified scaling/splitting/arrangement/repair/orientation actions, and saves a new `.3mf` project for inspection.
5. `validate_for_slicing` reports what it can actually measure: extents, bed/height bounds, unsupported geometry warnings, mesh checks, material/profile mapping and slice estimates. Keep “printable in slicer” separate from “physically fits/functions as intended.”

The local worker should save a job bundle with original source, authored source, versioned scripts/parameters, exported mesh, Creality `.3mf`, validation report, application/tool versions and hashes. Preserve one immutable pre-edit artifact and write each change to a new version. Queueing/model orchestration stays outside the CAD tools; the user's local Qwen agent can select tools based on explicit intent, with the same job APIs usable by other agents.

This is a proposed interface, not a prototype or verification that these programs are installed. Creality actions execute against `wxGetApp().plater()` and thus require the GUI; existing bridge metadata is not a headless CAD service. See [`SlicerBridgeActionsObject.cpp`](../../src/slic3r/GUI/simple/bridge/SlicerBridgeActionsObject.cpp#L1824).

## Pre-slice qualification gates

Before slicing new or modified geometry, establish the inputs that matter to the requested object's purpose: coordinate frame and units, relevant overall/interface dimensions, and material preference. Functional or fitted parts additionally need the relevant tolerances/clearances, mating references, forces, temperature/exposure and assembly constraints. A decorative object does not require an irrelevant engineering load specification. Ask when a missing input affects correctness or fit; do not present agent-proposed dimensions as owner-supplied measurements. Object-specific policy may permit disclosed design defaults for unconstrained artistic geometry. Functional fit or load requirements cannot be established from “make me a bracket,” an STL alone, or the printer's build volume.

Then check source/mesh provenance, unit scale, bounds, nonmanifold/open/self-intersecting surfaces, intended part count, smallest walls/holes/gaps against the selected printer/material process, supports/bridges, bed fit, and whether splits/connectors reproduce the intended assembly. Have Creality Print slice the saved project and inspect its warnings and estimates. A successful mesh validation or slice is evidence of geometric/slicer acceptance only; it does not prove functional strength, dimensional fit, safe material use, or successful physical printing.

Acceptance values and thresholds remain unresolved until the owner supplies object-specific function, dimensions, tolerances, reference measurements and material/load context; this report deliberately supplies no physical dimensions or safety threshold.

## Evidence limits

The Creality findings are checked-in source/action definitions, not tests of live GUI behavior. External claims cite first-party vendor manuals/features only. No tool was installed, run, or tested; Mac version compatibility, Python runtime availability, exact import/export fidelity, geometry correctness, and printer-specific tolerances remain unverified.
